# GitHub Issue 优先级修复需求

## 背景

2026-07-11 从 `Paikchu/PeakLog` 拉取到 71 个未关闭 issue：8 个 High、25 个 Medium、38 个 Low。本需求以安全、跨账号数据隔离、不可逆数据丢失、核心发布阻断、用户可见功能缺陷、维护性为顺序处理。

## 非目标

- 不在未验证前关闭 GitHub issue。
- 不在单次改动中重构整个本地存储或云同步架构。
- 不推送、部署或修改远端 Supabase，除非后续修复方案明确列出并获得确认。

## 全局验收

- 每个 issue 有根因证据、失败回归测试、最小修复和通过验证。
- P0/P1 需在 iOS 模拟器、数据库迁移/权限测试、Edge Function smoke test 三个对应层面验证。
- 每个完成批次在 `docs/logs/` 记录实际改动、验证命令、未解决风险和对应 issue。
- 每批次完成后再询问是否提交 commit；不自动关闭 issue，除非另行授权。
