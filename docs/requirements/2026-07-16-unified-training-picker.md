# 统一训练选择器与有氧 RPE 精简

## 目标

- 用户点击 Today 页“添加训练计划”后，直接进入统一的“选择运动”页面。
- 力量动作和有氧活动在同一个选择器中完成选择，不再经过“力量 / 有氧”前置分流页。
- 有氧不再采集或展示 RPE；力量训练现有的组级 RPE 保持不变。

## 交互范围

- 保留现有力量动作选择器的搜索、推荐、分类筛选、多选和自定义动作能力。
- 将页面标题从“选择力量”调整为“选择运动”。
- 在现有分类栏加入“有氧”Tab。
- “有氧”Tab 内提供跑步、骑行、椭圆机、爬楼机四个活动。
- 力量动作仍可多选，并进入原有组数、重量、次数表单。
- 有氧活动进入目标表单；跑步和骑行填写目标时长及可选距离，椭圆机和爬楼机只填写目标时长。
- 用户从有氧表单返回选择器时，保留此前的选择与已填写内容。

## RPE 边界

- 删除添加有氧计划时的目标 RPE 输入。
- 删除完成有氧计划和手动记录有氧时的实际 RPE 输入。
- 有氧计划卡、完成记录和历史卡不再显示 RPE。
- 新增或生成的有氧计划与记录不再写入 RPE。
- 力量训练每组的 RPE 输入、保存和展示不变。
- 为兼容旧客户端和已有数据，现有可选 RPE 字段暂不做破坏性数据库删除；旧值允许解码和同步，但不进入当前 UI。

## 数据与权限影响

- 统一选择器只改变客户端选择结果的表达和导航，不改变用户归属、RLS 或记录所有权规则。
- 有氧活动继续保存为 `cardio` 计划项，力量动作继续保存为 `strength` 计划项。
- 旧跑步记录缺少活动类型时仍按跑步解码。
- 周计划生成器和周中重排停止生成有氧 RPE，保留旧载荷的读取兼容。

## 失败路径

- 动作库加载失败时保留现有错误或空态，不自动退回已删除的类型选择页。
- 有氧目标时长无效时禁止保存；距离为空时允许保存，非正数或非法格式时禁止保存。
- 保存失败时停留在当前表单并显示错误，避免重复创建计划项。
- 未部署有氧迁移时不得把 PostgREST Schema 错误误报为客户端解码错误。

## 不做范围

- 不改变 Today 计划卡的力量训练流程。
- 不删除力量 RPE。
- 不新增有氧类型。
- 不重命名 `running_workouts` 表或本地 `runningRecords` 兼容键。
- 不在本次执行 Supabase 线上部署；部署需要单独授权。

## 验收标准

- 点击“添加训练计划”后直接显示“选择运动”，不出现“力量 / 有氧”选择页。
- 力量分类、搜索、推荐、多选和自定义动作行为无回归。
- “有氧”Tab 可选择跑步、骑行、椭圆机和爬楼机，并进入对应目标表单。
- 所有有氧新增、完成和手动记录表单均无 RPE；力量组表单仍有 RPE。
- 跑步和骑行支持可选距离；椭圆机和爬楼机不显示距离字段。
- 新增有氧计划、完成记录、历史展示、本地持久化和云映射均不依赖 RPE。
- 旧跑步数据和带有旧 RPE 的有氧数据仍可解码，不触发本地状态重置。
- 重复提交不会创建两条相同计划项或完成记录。
