# 动作选择器情境推荐（自由训练日）

## 背景
Picker 首屏目前是静态「最近使用」（最近度+频次），不感知训练情境：昨天练了腿，今天打开还是推腿的动作；今天已经勾了卧推，推荐区也不会顺势浮出胸部辅助动作。目标是让用户在推荐区内直接命中当天想练的动作，尽量不进入筛选/搜索。

## 目标
1. 推荐区取代「最近使用」成为 Picker 首屏唯一推荐入口（信号合并，不再有独立最近使用区）。
2. 恢复规避：大肌群（胸/背/腿/肩/臂）近 2 个自然日内练过 → 该肌群动作从推荐区**硬排除**；核心/全身仅规避 1 个自然日。仅作用于推荐区，分组列表与搜索不受影响。
3. 顺势推荐：根据"今日已选"（本次 Picker 勾选 ∪ 今日计划已有动作 ∪ 今日已记录训练）推荐同肌群动作，历史共现（经常同一天一起练）的动作优先；勾选变化时推荐区**实时重排**。
4. 去重：今日已选动作从推荐区硬排除（仅排完全相同动作，变体属于合法推荐）。
5. 协同递进：某肌群今日已选 ≥3 个动作后，同肌群降权、协同肌群上浮（胸→肩/臂，背→臂，肩→臂，腿→核心，全身→核心）。
6. 空态：今日无任何已选时，按"休息最久的大肌群"优先，组内按个人常用度（频次+近度）排序，隐式适配任何分化模式。
7. 冷启动：无训练历史时退化为种子库 popularity 排序。

## 明确不做
- 不加推荐原因副标题/标签（行样式与现有一致：动作名 + 器械·肌群 + 上次数据摘要）。
- 不接大模型：纯本地确定性规则打分，范围限制在设备内数据；规则引擎接口为未来接入模型预留（推荐入口收敛为单一纯函数）。
- 不做显式分化识别（推拉腿/五分化等），依赖"距上次训练天数"的隐式轮换。
- 不改 Picker 其余交互（chips/搜索/多选/自定义创建）。

## 验收
- 昨天只练了腿：打开 Picker，推荐区不出现任何腿部动作；分组列表和搜索仍能找到腿部动作。
- 前天练核心：核心动作可以出现在推荐区（核心仅规避 1 天）。
- 勾选卧推后：推荐区实时重排，历史上常与卧推同练的动作与胸部动作上浮，卧推本身消失。
- 今天已记录了胸部训练，再打开 Picker 补计划：胸部不被恢复规避误杀（今日练过 = 今日方向，而非"需要休息"）。
- 无历史数据的新用户：推荐区为高 popularity 动作，功能不报错。
- `tests/exercise_recommendation_test.swift` 覆盖以上场景；`xcodebuild test` 通过；模拟器手动验证实时重排动画流畅。
