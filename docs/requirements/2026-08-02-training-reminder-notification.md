# 需求文档：训练提醒通知

日期：2026-08-02
状态：已对齐（技术路径由用户拍板：本地通知优先，远程推送留作后续独立需求）

## 1. 需求背景

用户会忘记当天的训练。App 目前没有任何主动提醒能力——`UserNotifications` 在全仓库零引用。

同时 `ProfileScreen` 里已经存在一个「通知」开关（`UserPreferences.notificationsEnabled`，已随 Profile 同步到 Supabase），但**没有任何消费方**：打开或关闭它对用户没有任何可观察影响。本需求的本质是把这个已有开关接上真实实现，而不是新增第二个通知设置。

## 2. 目标与非目标

### 目标

- 在有训练安排的日子，按用户设定的时间发出一条本地通知，提示别忘记今天的训练。
- 复用已有的 `notificationsEnabled` 开关作为总闸。
- 提供可调的提醒时间（默认 18:00）。

### 非目标（本期不做）

- **远程推送 / APNs**：不加 `aps-environment` entitlement、不建 device_token 表、不写发送用 Edge Function、不配 pg_cron。留作后续独立需求。
- **提醒时间跨设备同步**：提醒时间按设备本地存储（比照 `ThemeManager` 的 appearance），不动 Supabase schema 与同步契约。
- 不做多次提醒、稍后提醒（snooze）、自定义文案。
- 不做通知点击后的深链跳转（点击仅打开 App 到默认页）。

## 3. 交互与规则

### 通知内容

- 标题：`别忘了今天的训练` / `Don't forget today's workout`
- 正文：`今日：<计划标题> · <N> 个动作`，标题降级链复用 `TodayPlanHeader.resolve`（计划标题 → focus → 「今日训练」兜底）。
- 语言跟随 App 当前语言（`String(localized:)` 在排程时求值）。

### 何时提醒

在设定时间提醒，当且仅当：

1. `notificationsEnabled == true`；
2. 系统通知授权已获得；
3. 当天在激活周计划里**有动作**（`exercises` 非空——空动作日即休息日，不提醒）；
4. 当天**尚未开始训练**（`completedProgressUnits == 0`）——已经开始就说明没忘，不打扰；
5. 提醒时刻尚未过去。

### 关键实现约束（必须写进设计）

iOS 不允许在通知触发那一刻执行逻辑判断，只能**预先排程**。因此方案是：按设备上已有的整周计划，为未来每个符合条件的日子各排一条 `UNCalendarNotificationTrigger`（非重复、精确到年月日时分），并在下列时机**全量重排**（先清空本功能的 pending 请求再重建）：

- App 进入前台 / 退到后台；
- 用户切换通知开关或修改提醒时间；
- 云端 pull 落地导致计划变化（通过前台重排覆盖）。

已知取舍：服务端 replan 后，若用户一直不打开 App，本地排程会停留在旧计划，直到下次前台重排。这是选择本地通知路径的已知代价，已与用户确认。

### 权限

- 不在启动时索要权限。用户**首次把通知开关打开**时才 `requestAuthorization(.alert/.sound/.badge)`。
- **开关显示的是有效状态 = 偏好 ∧ 系统授权**，而不是单看 `notificationsEnabled`。原因（模拟器验收时暴露）：`notificationsEnabled` 默认就是 `true`，若只看它，全新安装的用户会看到一个写着「开启」、却因为从没申请过授权而永远不响的开关，且永远不会被问到是否允许通知。改成有效状态后，全新安装显示「关闭」，用户去打开它，才触发授权框。
- 用户在系统设置里拒绝授权时，开关回落到关闭；只要偏好仍为 `true`（即用户确实想要提醒、是 iOS 在挡），通知行下方显示引导去系统设置的文案。用户自己主动关掉提醒时不显示该文案。

## 4. 数据与权限影响

- Supabase schema / RLS / Edge Function：**无改动**。
- 云端同步契约：**无改动**（复用已有的 `notificationsEnabled`）。
- 新增设备本地存储：`UserDefaults` 键 `peaklog.trainingReminderTime`（`HH:mm`）。

## 5. 验收方案

- [ ] 通知开关关闭 → 无任何 pending 通知请求。
- [ ] 通知开关打开且已授权 → 未来每个「有动作且未开始」的计划日各有一条 pending 请求，休息日和已开始的日子没有。
- [ ] 修改提醒时间 → pending 请求的触发时刻同步更新。
- [ ] 当天完成任意一组后重排 → 当天的 pending 请求被移除。
- [ ] 拒绝系统授权 → Profile 显示引导文案，不残留 pending 请求。
- [ ] 中英文下通知标题与正文均正确本地化。
- [ ] 纯逻辑排程规则有可独立运行的回归测试；iPhone 17 Pro Max 模拟器验证真实通知弹出。
