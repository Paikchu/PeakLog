# 有氧训练计划

## 目标

- 周训练计划可以同时包含力量动作和有氧活动。
- 首版支持四种有氧类型：跑步、骑行、椭圆机、爬楼机。
- Today 页面按活动类型展示有意义的计划指标，不复用力量训练的组数、重量、次数 UI。
- 用户完成计划内有氧活动后，实际记录、计划完成状态、历史页和云同步保持一致。

## 计划指标

| 类型 | 必填计划指标 | 可选计划指标 | Today 计划 UI |
| --- | --- | --- | --- |
| 跑步 | 时长 | 距离、目标 RPE | 时间、公里数、强度 |
| 骑行 | 时长 | 距离、目标 RPE | 时间、公里数、强度 |
| 椭圆机 | 时长 | 目标 RPE | 时间、强度 |
| 爬楼机 | 时长 | 目标 RPE | 时间、强度 |

- 时长以分钟存储，必须大于 0。
- 距离以公里存储；椭圆机和爬楼机不要求距离。
- 强度使用 RPE 1–10，避免依赖不同器械不兼容的阻力档位。
- 跑步和骑行允许只按时间规划；距离不是强制字段。

## 交互

- Today 的同一天可以混合展示力量动作和有氧活动，并保持计划顺序。
- Today 的“添加计划动作”入口先选择力量或有氧；选择有氧后可设置活动类型、目标时长、可选距离和目标 RPE。
- 力量动作继续使用现有组数卡片和专注训练流程。
- 有氧活动使用独立卡片，显示运动图标、类型、目标时间、可选距离和目标 RPE。
- 点击有氧卡片的开始操作进入有氧执行态；结束时录入实际时长、可选实际距离和实际 RPE。
- 保存成功后，该有氧计划项显示为已完成，并生成一条历史记录。
- 保存失败时保留输入并显示错误，不提前标记计划完成。
- 有氧计划项支持删除和排序；不提供“添加一组”或重量、次数编辑。

## 数据与生成

- 计划项需要明确区分力量与有氧，并为有氧保存活动类型及目标指标。
- 现有跑步记录升级为通用有氧记录，兼容已落库的跑步数据；旧记录默认识别为跑步。
- 周计划生成和周中重排可以生成四种有氧活动；生成器必须根据用户训练天数、单次时长和相邻力量日恢复需求安排有氧。
- 有氧活动不计入力量组数进度；计划总进度按“力量组完成数 + 有氧活动完成数”计算。
- 云端迁移只新增字段或兼容结构，不改写已部署迁移，不丢失现有跑步记录。
- RLS 继续按 `user_id = auth.uid()` 隔离；本需求不扩大任何访问权限。

## 验收标准

- [ ] 同一天可按顺序展示力量动作、跑步和器械有氧卡片。
- [ ] 用户可从 Today 手动添加四种有氧计划项；保存后立即出现在今日计划，并保留目标指标。
- [ ] 跑步、骑行卡片正确处理“仅时间”和“时间 + 距离”。
- [ ] 椭圆机、爬楼机只要求时间，且可显示目标 RPE。
- [ ] 完成有氧计划后只创建一次记录，并正确更新计划进度与历史页。
- [ ] 保存失败、重复提交、离线保存和 App 重启恢复不会产生重复记录或错误完成状态。
- [ ] 旧本地 JSON 和云端 `running_workouts` 数据仍可读取，并显示为跑步。
- [ ] 周计划生成与周中重排的校验器拒绝未知活动类型、非正时长、负距离和越界 RPE。
- [ ] iOS 单元测试、后端测试与 iPhone 17 Pro Max / iOS 26.5 模拟器主路径通过。

## 不做范围

- 游泳、划船机、跳绳和 HIIT 间歇模板。
- GPS 路线、配速分段、心率区间和 Apple Health / Fitness 同步。
- 自动读取跑步机、单车或器械数据。
- 本轮不部署 Supabase 线上迁移或 Edge Function；线上部署需要单独授权。
