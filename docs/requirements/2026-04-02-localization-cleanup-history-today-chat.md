# 历史页 / 今日页 / 聊天气泡计划卡 本地化系统清理需求

## 背景
- 当前项目已经接入 `Localizable.xcstrings`，但历史页、今日页、聊天计划卡仍存在多种不一致写法：
- 直接英文硬编码
- 直接中文硬编码
- 通过字符串插值绕过本地化
- 同一页面混用 key、本地文案和拼接模板

这会导致中文环境下仍出现英文标题，英文环境下又出现中文文案，页面观感不统一。

## 目标
- 对以下区域做一轮系统性本地化清理：
- 训练历史页
- 今日页
- 聊天气泡中的周计划卡 / 今日计划卡

## 范围
- 仅修改 iOS App `PeakLog`
- 不修改 backend schema
- 不改动 Supabase Edge Function
- 本次重点清理 UI 展示层与可访问性文案

## 需求说明
### 1. 历史页
- `Week Plan / Current Plan` 区域必须随系统语言切换
- 日历下方的计划空态必须随系统语言切换
- 当天完成训练的新卡片组件必须纳入统一本地化体系
- 日期标题、摘要、副标题、来源标签、指标标题都不能再直接写死中文或英文

### 2. 今日页
- 顶部标题、摘要卡、section 标题、副标题、空态提示、跑步手动录入 sheet、AI 浮层状态文案必须统一走本地化
- `Week of ...`、`... sets completed`、`距离/时长/条数` 等参数化文案必须改为格式化 key
- 不允许继续使用 `"Week of \(...)”` 这类直接插值

### 3. 聊天气泡计划卡
- `Current Plan`、`Week of ...`、`Today` 等标题必须本地化
- 卡片中的训练日状态显示不能依赖英文 `capitalized`
- 计划卡和今日计划卡展示文案要与历史页 / 今日页保持同一套语言语义

### 4. 统一规则
- 固定文案：使用 `Text("localization.key")` 或 `String(localized:)`
- 参数化文案：统一使用格式化 key + `String(format:locale:)`
- 可访问性文案：必须进入字符串表，不能继续硬编码英文
- 新增历史页已完成训练组件中的中文直写，必须全部收口到 `Localizable.xcstrings`

## 验收标准
- 中文环境下：
- 历史页、今日页、聊天计划卡不再出现英文标题或英文摘要
- 历史页已完成训练组件不再出现未本地化中文直写拼接
- `Week of ...`、`sets completed`、跑步摘要、section 副标题都显示为自然中文

- 英文环境下：
- 以上区域不再出现中文标题或中文说明
- 新历史组件中的 `当天完成 / 力量训练 / 跑步与有氧 / 未记录重量 / 手动` 等文案能正常显示英文

- 技术验收：
- 本地化字符串来源统一
- 不再保留关键硬编码文案
- iOS 工程可成功构建
- 需补实现日志，记录本次清理范围、核心改动和验证结果
