# 首页今日计划问题定位需求

## 背景

用户在首页“今日计划”区域发现两个问题：

1. 点击某组的重量后进入编辑弹层，输入新重量后无法顺利点击“完成”，导致重量修改不能成功保存。
2. 当前 AI 规划出的训练计划在首页展示时，动作的负重信息丢失，多个原本不应视为自重的动作都显示为“自重”。

本次需求先以“定位根因并给出可执行修复方案”为目标，不在结论不清晰的情况下直接修改。

## 需求目标

1. 明确“重量无法点击完成”问题发生在哪一层：
   - 首页 SwiftUI 交互层
   - ViewModel 状态提交层
   - Supabase 计划更新接口层
2. 明确“计划全部显示自重”问题发生在哪一层：
   - 首页展示逻辑
   - iOS 计划数据模型
   - backend agent prompt / tool schema / plan 持久化链路
3. 给出清晰的修复边界，判断：
   - 是否只需修改 `PeakLog` iOS app
   - 是否必须同步修改 `backend` 中的 Supabase Edge Function

## 已确认的事实

1. 首页“今日计划”重量编辑使用 `ValueEditSheet`，弹层固定高度为 `220`，输入框自动聚焦并弹出 `decimalPad` 键盘。
2. 首页“自重”展示逻辑当前完全依赖 `targetWeight == nil`。
3. 训练计划模型 `TrainingPlanExercise` / `TrainingPlanSet` 当前没有显式的动作类型或负重类型字段。
4. backend 中计划创建和调整沿用同一套 agent prompt；该 prompt 当前偏向跑步记录，不足以稳定约束力量训练计划的负重输出。

## 验收标准

### 定位验收

1. 能明确指出重量编辑问题的根因代码位置。
2. 能明确指出“全部显示自重”问题的根因代码位置。
3. 能明确说明两个问题分别属于 iOS 问题还是 backend 问题，或属于双端协同问题。

### 方案验收

1. 修复方案必须说明修改点、影响范围和风险。
2. 若涉及 agent 行为，方案必须采用 prompt + structured schema 约束，而不是硬编码动作名称匹配。
3. 若涉及显示逻辑，方案必须避免把“重量为空”和“动作是自重”混为同一语义。
