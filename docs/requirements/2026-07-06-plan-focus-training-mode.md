# Plan 页专注训练模式(合并 TrainingSessionScreen)

## 背景与目标

- 取消独立的全屏训练执行页 `TrainingSessionScreen`(fullScreenCover),把"开始训练"合并进 Today plan 页。
- 点击「开始训练」后,同一页面进入**专注模式(Focus Mode)**:当前未完成动作流动到屏幕中间,其余动作退后;逐组确认、逐动作流转,直到全部完成。
- 允许用户滑动切换到任意动作优先完成;之后流转回到最早的未完成动作。
- 训练结束后展示总结:本次训练对各身体部位的刺激强度。

## 一、核心概念与状态机

页面只有一份卡片列表,两种展示状态,不再有第二个页面:

| 状态 | 说明 |
|---|---|
| 浏览模式 Browse | 现状 plan 页:summary + 动作卡片列表 + 跑步记录等 |
| 专注模式 Focus | 当前动作卡片放大居中,其余折叠/退后;底部出现大确认按钮 |

指针规则:

- **当前动作** = 按 plan 顺序第一个仍有未完成组的动作;用户滑动锁定其他动作时,被锁定的动作成为当前动作。
- **当前组** = 当前动作内第一个未完成的组(允许点任意未完成组,指针始终重算为"第一个未完成")。
- 手动切换的动作完成后,指针**回到按 plan 顺序最早的未完成动作**(不是继续往下),与需求一致。
- 动作全部组完成 → 播放完成动画 → 自动流转到下一个当前动作。
- 所有组完成 → 弹出训练总结。

进入/退出:

- 入口:现有「开始训练」按钮(dock 上),仅当今日计划组数 > 0 时可见(维持现状)。
- 退出方式一「最小化」:回到浏览模式,但 session 仍活跃(顶部保留"训练中 n/m"胶囊,点击回到专注模式)。这替代了原来的 ✕。
- 退出方式二「结束并保存」:有未完成组时提示"还有 x 组未完成,确认结束?";写入已完成组(沿用现有 pending-completion 落库逻辑)。
- 退出方式三「取消本次训练」:二次确认,放弃不落库(维持现状语义)。
- App 杀掉/切后台:session 需可恢复(现有 `activeLiveWorkout` 是内存态,需评估持久化到本地 DB;至少切后台回来要还原)。

## 二、需求补齐(原需求未覆盖的细节)

1. **组的撤销**:专注模式允许取消勾选(TrainingSessionScreen 现在允许 toggle,浏览模式的 Today 页是 `disabled`,需统一为:session 内可撤销,已落库的不可撤销)。
2. **组间休息计时器**(强烈建议纳入):完成一组后自动开始休息倒计时(默认 90s,可配置/可跳过),显示在确认按钮位置;倒计时结束 haptic 提醒。这是"流转节奏"的核心,也是 Live Activity 的天然内容。可以作为 Phase 2。
3. **跳过动作**:当前动作长按/菜单提供「跳过」,跳过的动作沉到队尾,结束时按未完成处理。
4. **训练中编辑**:专注模式下仍可改重量/次数(复用 `ValueEditSheet`)、加组/减组;当前组数据变化需同步 Live Activity。
5. **RPE**:保留现有 context menu 方案;另在勾选完成后的短暂窗口展示一排 RPE chips(6–10)供快速补记,不选则跳过。
6. **已完成动作的处理**:滑动可以浏览到已完成动作(显示完成态摘要),允许进入修改(撤销某组),但不会成为自动流转目标。
7. **Live Activity 一致性**:手动滑动切换当前动作后,Live Activity 展示的"当前动作"要同步更新;Live Activity 完成的组回 App 后合并(维持现状),并驱动指针与滚动位置更新。
8. **进入专注模式前已完成部分组**(浏览模式勾掉的):指针直接落在第一个未完成动作,已完成组显示为折叠完成态。
9. **屏幕常亮**:专注模式下 `isIdleTimerDisabled = true`,退出恢复。
10. **Rest 日/无计划**:无入口,维持现状。
11. **无障碍**:VoiceOver 朗读"当前第 x 组,目标 60kg × 8";Dynamic Type 下卡片自适应;**Reduce Motion 时所有位移/缩放动画降级为 crossfade**。
12. **中断场景**:训练中来电话/切走 → Live Activity 已覆盖;第二天未结束的 session → 启动时提示"有未完成的训练"并给结束/放弃选项。

## 三、身体部位刺激强度(数据缺口 + 算法)

**现状**:`TrainingPlanExercise` / `PlanLiveWorkoutExercise` 均无肌群字段,必须先补数据。

数据方案(建议 a+b 混合):

- (a) 内置静态映射表:常见动作名(中英文)→ 主动肌群(primary)+ 协同肌群(secondary)。覆盖 80% 常见动作,零成本零延迟。
- (b) 查不到时用已接入的 on-device Foundation Model 推断一次,结果写入本地缓存(exercise_name → muscles)。
- (c) 长期:AI 生成计划时直接带肌群标签落库(schema 加 `muscle_groups` 字段)。

肌群粒度建议 8 类:胸、背、肩、二头、三头、腿(股四/腘绳可再分)、臀、核心。

**强度算法**(训练学标准做法是"有效组数"而非容量):

```
每个肌群得分 = Σ(该肌群作为主动肌的完成组数 × 1.0 + 作为协同肌的完成组数 × 0.5)
等级:0 无 | 1–3 轻度 | 4–7 中度 | 8–12 高强度 | >12 极高
```

可选加权:RPE ≥ 9 的组 ×1.2。展示时给等级 + 组数,不给伪精确的百分比。

**展示**:总结卡内按得分降序列出肌群条(胶囊条形图,v1);v2 再考虑人体热力图。同时展示:总组数、总容量(kg)、训练时长、RPE 均值、是否 PR,和 on-device coach 的一句话点评。

## 四、UI 方案(三选一,推荐 A)

### 方案 A:焦点流 Focused Flow(推荐)

同一个 ScrollView 从浏览模式连续变形:

- 顶部:summary card 压缩为紧凑条 —— 进度环/进度条 + 「n/m 组」+ 最小化按钮。
- 中部:动作卡片垂直排列,滚动吸附(`.scrollTargetBehavior(.viewAligned)`),**当前动作卡片在屏幕中心且完全展开**;已完成动作折叠成带对勾的摘要行堆在上方;后续动作折叠为「名称 + n 组」摘要行排在下方,降透明度。
- 当前卡片内:当前组是大号高亮行(大字 重量 × 次数,左侧 accent 指示条),其余组小号;上次表现小字参考。
- 底部:全宽大确认按钮「完成第 x 组」(Liquid Glass,替换/覆盖 dock 位置),上方一排 RPE chips(可选)。
- 滑动切换 = 就是滚动:停止时居中的卡片展开点亮,成为当前动作。

优点:与现有页面同构,"合并"语义最自然,过渡动画是布局连续变化而非页面跳转;滑动切换天然支持。缺点:滚动吸附 + 折叠/展开联动需要细调。

### 方案 B:牌堆 Deck

当前动作一张大卡居中,下一张在底部露出边缘,完成的卡飞向顶部缩小堆叠;上下滑动换牌。聚焦感和仪式感最强,但与现有列表形态差异大、全局信息弱、实现成本最高。适合作为 v2 的"沉浸开关"。

### 方案 C:手风琴时间线 Accordion

保持完整列表,同时只展开一个卡片(当前动作),其余全部折叠为单行;自动滚动让展开卡居中。实现最简单(卡片加 expanded/collapsed 两态),但"流动到屏幕中间"的聚焦感最弱。

**推荐:A(本质上是 C 的滚动吸附增强版)。** 折叠态复用 C 的单行摘要,滚动行为用 A。

## 五、动画规划

设计原则:全程**没有页面跳转**,只有一份视图的布局插值;所有动画用 spring,不用 ease 曲线;haptic 与视觉同拍。

### 1. 进入专注模式(点「开始训练」)

三拍连续动作,总时长 ~700ms:

1. **0–150ms 收场**:跑步记录等无关 section 淡出(opacity → 0 + 向下 8pt);summary card 收缩为顶部紧凑条(高度动画 + 文字 crossfade)。
2. **150–550ms 聚焦**:非当前动作卡片折叠为摘要行(高度 spring),ScrollView 同帧滚动使当前卡片居中 —— 视觉上就是"当前动作流动到屏幕中间"。当前卡片 scale 1.0 → 1.02 → 1.0 收尾。
3. **450–700ms 落座**:底部确认按钮从 dock 位置升起(offset + opacity,damping 0.7 带一点弹性);当前组行左侧 accent 指示条展开。

参数:布局重排 `.spring(response: 0.5, dampingFraction: 0.82)`;按钮 `.spring(response: 0.4, dampingFraction: 0.7)`。

技术要点:iOS 17+ `scrollPosition(id:)` + `.scrollTargetLayout()` 控制居中;卡片用 `visualEffect { content, proxy }` 按"到屏幕中心距离"连续插值 scale(0.94–1.0)/opacity(0.55–1.0),这样聚焦是连续函数,滑动过程自然过渡,无离散跳变。

### 2. 完成一组

- 勾选:circle → checkmark.circle.fill,symbol bounce + scale 1 → 1.25 → 1(~300ms);该行背景闪一层绿 tint 后回落;haptic `.success`(已有)。
- 完成的组行高度压缩(46 → ~32)变暗成摘要;下一组行升格为大号高亮行,accent 指示条滑到它左侧(同一元素位移,不是消失重现)。
- 顶部进度环/条 spring 前进,数字用 `.contentTransition(.numericText())` 滚动。
- 若启用休息计时:确认按钮原位变形为倒计时环(morph,不换控件)。

### 3. 动作完成 → 流转到下一动作

链式序列(`withAnimation` 链或 `PhaseAnimator`),总长 ~1.4s:

1. **0–300ms**:最后一组勾选动画。
2. **300–900ms**:整卡完成态 —— 卡片描边扫过一圈 accent 光,标题行打上对勾,haptic 双击感(`.success` + 轻 `.impact`);随后整卡折叠为完成摘要行。
3. **900–1400ms**:ScrollView spring 滚动,下一个未完成动作滑到中心展开;卡片内 set rows 交错入场(每行延迟 35ms,opacity + 向上 6pt)。

停留一拍(300–900ms 的完成态)是刻意的:给用户"这个动作结束了"的确认感,不能瞬间跳走。

### 4. 滑动切换动作

- 滚动中:`visualEffect` 连续插值,离中心越远越小越淡(可选 blur 0–2pt,注意性能)。
- 吸附停止:居中卡片展开为完整态,accent 边框呼吸一次(opacity 0.4 → 1 → 0.7,~600ms);底部按钮文字 crossfade 更新为「完成 {动作名} 第 x 组」;轻 haptic `.selection`。
- 快速连续滑动时不触发展开动画,停稳 ~150ms 后才展开(防抖)。

### 5. 全部完成

- 进度环填满 → 短暂 hold → 全屏轻量 celebration(粒子或环形光晕,克制,不做满屏彩带)→ haptic `.success` ×2。
- 总结卡以 sheet(`.presentationDetents([.medium, .large])`)升起;肌群强度条交错生长(每条延迟 60ms,spring),数值 numericText 滚动。
- 用户确认后走现有 `confirmPlanLiveWorkout()` 落库。

### 6. Reduce Motion

所有位移/缩放/滚动动画替换为 opacity crossfade;自动滚动改为无动画直接定位;celebration 只保留 haptic。

## 六、UX 原则清单

- **单手可达**:确认是唯一高频操作,放底部中央全宽大热区;RPE、跳过等次级操作不挡主路径。
- **聚焦但不禁锢**:任何时候可滑走看其他动作、可编辑数值、可最小化回浏览模式;专注模式是引导,不是锁。
- **误触可逆**:session 内勾选可撤销;取消训练二次确认;结束时未完成组明确列出。
- **信息层级**:训练中只突出"现在要做什么"(重量 × 次数大字);上次表现、AI 建议退为小字;浏览模式的全局信息在专注模式全部收起。
- **状态永不丢**:切后台、锁屏、Live Activity 操作、杀 App 后回来,session 与滚动位置都恢复。
- **节奏感**:组完成 → 休息倒计时 → 下一组,动画时长服务于节奏(完成态停留一拍),而不是炫技。

## 七、待确认的问题(默认取推荐值)

1. 滑动吸附停稳即切换当前动作,还是需点击确认?**推荐:停稳即切换**(有防抖)。
2. 休息计时器进 v1 还是 v2?**推荐:v1 做最简版(固定 90s 可跳过),配置项 v2。**
3. 肌群映射走静态表 + 本地模型兜底?**推荐:是;schema 加字段放 v2。**
4. 手动切换动作完成后回到"最早未完成"——若用户连续手动切了多个,均回最早未完成?**推荐:是,规则单一。**
5. 总结页是否需要人体热力图?**推荐:v1 条形胶囊,v2 热力图。**
